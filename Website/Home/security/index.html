Security

This page is the public shape of the security architecture. It describes boundaries and the standard of evidence. It does not publish addresses, host names, credentials, or private endpoints.

  • Access boundaries

    People, agents, and services reach systems through a boundary that matches the work. A public page is not an operator console. Crossing a boundary is a deliberate step.

  • Verification

    State is accepted when there is evidence for it. A claim, a commit, or a command is not that evidence by itself.

  • Evidence

    Execution should leave a record that can be checked later: what was asked, what ran, and what the system reported back.

  • Deployment distinction

    Source and the running system are different facts. Shipping a change and proving the running system took that change are separate steps.

  • Operational controls

    Important operations stay controllable by people. Agents can prepare work inside a bound. The control that performs it stays visible.

  • Monitoring

    Public monitoring is the status feed. It shows a reading when the feed has one. It does not invent a healthy system to fill a gap. Status

  • Security documentation

    Security material belongs in the RootRecord Library, with the rest of the durable knowledge. Private material stays there. This page does not copy it out. Knowledge

  • Change management

    A change should remain understandable after it lands: what it was for, where it applies, and how someone can tell whether it took effect.

  • Continuity

    Security includes being able to operate and repair the system without starting from zero. History, context, and evidence are part of that. About
