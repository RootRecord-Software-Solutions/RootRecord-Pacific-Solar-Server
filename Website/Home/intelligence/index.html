Agents

An agent reads context, determines bounded work, and carries that work through the controls that apply to it. An agent is an operator inside the system. This page has no public agent count.

Agent model

Architecture, not a live roster.

  1. Read context
  2. Determine bounded work
  3. Prepare action
  4. Pass through control
  5. Execute
  6. Record evidence
  7. Persist result

Persistent context

Durable context is how the next person or agent can see what the system already learned. Architecture, procedures, and prior decisions stay in the knowledge layer. Without that layer, each session starts blank. Knowledge

Controlled execution

Actions pass through the boundary that fits the operation. Control is the point where a decision becomes an allowed action. Unrestricted execution is not the model.

Verification

A proposed action is not evidence. A command is not evidence. A commit is not proof of deployment. A successful request is not necessarily proof of system state. Evidence is what the system can actually report and what can be checked later. Security

Persisted state

The result of accepted work belongs in the data layer, where a later check can read it. A sentence that something ran is not that record. Data
